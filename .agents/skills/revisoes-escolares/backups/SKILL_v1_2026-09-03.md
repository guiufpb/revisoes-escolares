# Revisoes Escolares

Use esta skill como **roteador operacional**, nao como substituto das regras do repositorio.

## 1. Fonte de verdade e precedencia

Antes de alterar codigo, siga nesta ordem:

1. `AGENTS.md`.
2. `documentacao/ambiente-interativo/INSTRUCOES_PROJETO.md`.
3. `documentacao/ambiente-interativo/INVENTARIO_IMPLEMENTACOES.md`.
4. Para nova revisao: `ambiente_interativo/revisoes/MODELO_NOVA_REVISAO.txt`.
5. Quando precisar de historico/testes reais: `ambiente_interativo/RELATORIO_TESTE_INTERATIVO.txt`.
6. `package.json` para comandos vigentes.
7. Implementacao atual e uma revisao equivalente.

Se houver divergencia, prevalecem `AGENTS.md`, as instrucoes do projeto e a implementacao atual.
Nao copie para esta skill regras que mudam com frequencia; releia os arquivos acima.

## 2. Preflight obrigatorio

Antes de qualquer escrita:

- execute `git status --short --branch`;
- identifique branch, `HEAD`, relacao com `origin/main` e arquivos pendentes;
- preserve prompts locais, stashes e alteracoes alheias;
- se houver trabalho rastreado ou codigo nao relacionado que possa conflitar com a tarefa, pare e reporte antes de misturar lotes;
- nunca use `git reset --hard`, `git clean -fd`, `git add -A`, `git add .` ou `git add -f` como atalho;
- nao faca commit, push, PR, merge ou publicacao sem autorizacao explicita para essa etapa.

Para nova revisao, crie branch propria `codex/<slug>` apenas quando a base estiver adequada e o usuario tiver pedido implementacao.

## 3. Entenda a entrada antes de codificar

Resolva explicitamente:

- crianca/perfil;
- serie;
- materia;
- assunto e data/prova quando relevante;
- material de referencia: sintese, PDF, prints, paginas ou revisao anterior;
- saida desejada: interativa, cartilha/PDF, simulado, gabarito, auditoria ou apenas planejamento;
- quantidade de questoes/pontos e restricoes especiais.

Se o material ainda precisa de interpretacao pedagogica ampla, prefira uma **sintese pedagogica curta e reutilizavel** antes da implementacao. Consulte `references/materiais-locais.md` e use `assets/modelo-sintese-pedagogica.md`.

## 4. Economize contexto por padrao

Aplique estes principios:

1. **REUSE BEFORE PROCESS** — reutilize sintese, OCR, paginas renderizadas e implementacoes equivalentes antes de processar novamente.
2. **LOCAL BEFORE MODEL** — use ferramenta local para trabalho mecanico/deterministico.
3. **FILTER BEFORE CONTEXT** — filtre paginas, trechos, logs e diffs antes de envia-los ao agente principal.
4. **VISION ONLY WHEN NEEDED** — use inspecao visual apenas quando imagem/layout forem pedagogicamente relevantes.

Nao re-OCRize ou rerenderize um PDF inteiro se ja houver sintese confiavel ou se apenas poucas paginas forem relevantes.
Nao despeje OCR, logs de testes ou diffs enormes no contexto principal; retorne resumos com evidencias.

Leia `references/materiais-locais.md` quando houver PDF, print, OCR, imagem, DOCX, planilha ou outro material bruto.

## 5. Orquestracao economica e subagentes

O agente principal e o responsavel pela decisao arquitetural e pela integracao final.
Use subagentes apenas quando a tarefa for independente, limitada e puder voltar como resumo curto.

Padrao recomendado:

- tarefa pequena/mecanica: um unico agente;
- nova revisao declarativa: agente principal planeja e escreve; use `revisoes_explorer` para exploracao read-only quando necessario; use `revisoes_auditor` para auditoria final objetiva;
- mudanca compartilhada ou regressao estrutural: mantenha o raciocinio principal em modelo forte e use subagentes apenas para investigacoes/read-only independentes;
- evite agentes paralelos escrevendo os mesmos arquivos.

Subagentes consomem tokens proprios. Nao os crie por padrao. Delegue somente se o subagente precisar de **menos contexto** que o principal.

Leia `references/orquestracao-economia.md`.

## 6. Escolha a infraestrutura antes de criar algo novo

Consulte primeiro o inventario e uma revisao equivalente.
Depois roteie:

- **Matematica visual/manipulativa**: leia `references/matematica.md`.
- **Matematica digitada/tabuada**: leia `references/matematica.md`.
- **Gramatica/Portugues, Historia, Geografia e questionarios declarativos**: leia `references/questionarios-e-audio.md`.
- **Ingles/audio**: leia `references/questionarios-e-audio.md`.
- **Leitura/PDF.js**: leia `references/leitura.md`.
- **Materia futura**: consulte inventario/modelo e prefira extensao opt-in; nao presuma biblioteca ou controlador inexistente.

Conteudo especifico fica em `ambiente_interativo/revisoes/<perfil>/` quando aplicavel.
Comportamento reutilizavel fica em controlador compartilhado somente quando a capacidade realmente precisa ser geral.
Nao reconstrua o ambiente nem crie controlador paralelo para trocar conteudo.

## 7. Contrato pedagogico e de estado

Preserve sempre:

`errar -> conferir -> corrigir -> conferir -> avancar -> voltar -> recarregar`

Garanta:

- erro recuperavel sem pular etapa;
- pontuacao sem duplicacao;
- estado visual e logico restaurados juntos;
- progresso isolado por perfil, materia, revisao e chave;
- `localStorage.clear()` proibido;
- limpar apenas a chave ativa;
- arrasto nunca como unico meio;
- clique/toque/teclado e foco visivel;
- manipulaveis reversiveis;
- `aria-live` para mensagens;
- celular 390 x 844 sem rolagem horizontal quando aplicavel;
- conteudo infantil original, simples e adequado a serie;
- evitar resposta livre quando varias respostas pedagogicamente corretas poderiam existir e o sistema aceitar apenas uma.

Para material impresso/simulado, inclua gabarito e siga as regras especificas do repositorio.

## 8. Privacidade e direitos autorais

Nunca publique:

- PDFs escolares reais;
- OCR bruto ou renderizacoes privadas;
- prints do caderno;
- pastas identificadas por aluna;
- documentos pessoais;
- caches, logs, `test-results`, `playwright-report`, `blob-report`, temporarios;
- prompts locais sem autorizacao.

Crie atividades, textos e ilustracoes proprios. Use materiais privados para delimitar o assunto, nao para reproduzir paginas literalmente.

## 9. Validacao proporcional ao risco

A politica de testes e exclusivamente a de `AGENTS.md`.
Para toda mudanca de codigo, normalmente execute:

- `npm run build`
- `npm run format:check`
- `npm run lint`
- testes Playwright direcionados ao fluxo alterado.

Use `npm test` global apenas pelos gatilhos atuais do `AGENTS.md`; nao invente regra paralela.
Mudanca declarativa pode ficar em testes direcionados quando a cadencia permitir.
Mudanca compartilhada/estrutural ou duvida de alcance antecipa a global conforme `AGENTS.md`.

Prefira testes reais e comandos deterministas a revisao imaginada pelo modelo.
Filtre saidas longas e retorne apenas erros relevantes ou contagens PASS/FAIL.
Leia `references/testes-git-publicacao.md`.

## 10. Gates de parada

Pare e informe antes de prosseguir quando:

- a base Git estiver contaminada por trabalho nao relacionado;
- a tarefa aparentemente declarativa exigir mudanca em controlador compartilhado nao prevista;
- houver necessidade de destruir/migrar progresso antigo;
- uma ferramenta local exigir instalacao/elevacao de privilegio nao autorizada;
- testes revelarem regressao compartilhada inesperada;
- material privado aparecer como candidato a versionamento;
- commit/push/merge forem necessarios sem autorizacao explicita.

Nao esconda problemas alterando testes para faze-los passar.

## 11. Encerramento de uma implementacao

Antes de declarar pronto:

- resuma ID, chave, arquivo, questoes/etapas/pontos e infraestrutura reutilizada;
- informe arquivos compartilhados alterados ou confirme que nao houve;
- informe testes realmente executados e resultados;
- informe se `npm test` global foi ou nao exigido pela cadencia;
- execute `git diff --check`;
- confirme privacidade;
- pare antes de commit/push/PR salvo autorizacao explicita.

Quando o usuario confirmar uso real por Alice/Mariana, registre essa validacao somente se solicitado ou se a etapa de documentacao estiver autorizada; nao invente fatos de uso.

Para staging/publicacao autorizados, siga `references/testes-git-publicacao.md` e preserve staging explicito.
